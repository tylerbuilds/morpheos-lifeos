# Contributing

Keep the everyday phone experience clear. Prefer small changes that work without an account or a new runtime dependency. Keep integrations optional and show unknown, stale and unconfigured states honestly.

Run the checks documented in the README. Include before/after screenshots for UI changes and exercise narrow screens, dark mode, keyboard navigation, saving and error states. Never include real account data or private addresses in tests.

Changes to authentication, file writes and adapter formats need meaningful regression tests. Avoid introducing a second scheduler or agent control system. Discuss large provider integrations in an issue first.
